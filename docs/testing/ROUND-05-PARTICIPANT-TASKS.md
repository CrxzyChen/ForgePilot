# AI Game Studio Round 05 participant tasks

You are evaluating a hash-pinned AI Game Studio candidate and a supplied
placeholder Tank project. This sheet contains product tasks, not implementation
instructions. Use only what the installed product makes visible.

## Rules

- Use the clean Windows profile or clean test computer assigned by the observer.
- Use only AI Game Studio and the standalone games it builds.
- Do not use a terminal, another IDE, the engine checkout, direct file editing,
  DevTools, DOM access, private APIs, or screen-coordinate automation.
- You may use help, diagnostics, project documents, and Skills visible inside
  Studio. Do not ask the observer how to perform a step.
- Enter supplied test credentials only through Studio Credential Management.
  Never paste a secret into Copilot, a project file, Diff, or this record.
- Provider calls may cost money. Make cost, candidate, and ChangeSet decisions
  only through the visible Studio gates.
- Say aloud what you expect when a state or next action is unclear. If you
  cannot continue, describe what you tried and stop safely.

## Canonical goal

Open the supplied Tank project. In Studio Copilot, ask Codex to upgrade the
playable placeholder game into a coherent, polished, standalone 2D Tank game.
It should establish an art direction, determine the required visual and audio
assets, use the configured generation tools, present paid calls and candidates
for your review, import approved resources, replace placeholder presentation,
complete the menu/HUD/help/pause/win/lose/restart experience, run and inspect
the game, fix failures, run tests and Replay, and build Windows Development and
Release packages. Make product, cost, candidate, and ChangeSet decisions when
Studio asks you.

You may phrase the goal naturally, but preserve that outcome and its safety
constraints.

## Journey A — Start and understand the work

1. Open the supplied project and play its current placeholder state.
2. Open Copilot, sign in if required, and submit the canonical goal.
3. Explain the visible Goal, current Plan step, connected engine capabilities,
   and any waiting or failed state.
4. Configure any missing credential or media route through normal Settings.
5. Stop before the first paid request, close Studio, reopen it, and continue the
   same Goal.

## Journey B — Generate and review media

1. Let Copilot prepare art direction, asset coverage, and generation briefs.
2. Review and approve one estimated image request.
3. Compare at least two candidates, reject one, and select one.
4. Review the resulting import ChangeSet, apply it, inspect provenance, undo it,
   then safely reapply or regenerate it.
5. Generate and review one required sound effect.
6. Cancel one job and retry one deliberately transient failure.
7. Change to a bounded budget policy and observe one allowed and one waiting
   request.

## Journey C — Finish and repair the Tank game

1. Continue the same Goal through the remaining reviewed visual and audio set.
2. Review understandable Prefab, Scene, UI, script, and audio ChangeSets.
3. Inspect menu, play, pause, win, lose, and restart checkpoints.
4. Use only the supplied visible test controls to exercise the seeded texture,
   layer/pivot, UI, audio, and packaged-resource failures.
5. Ask Copilot to diagnose, repair, verify, and if requested roll back each one.
6. Play movement, firing, collision, damage, destruction, score, pause, win,
   lose, restart, help, volume, and mute.

## Journey D — Interrupt and recover

The observer will tell you when to close or stop the tested process, but will
not tell you how to recover. After each assigned interruption:

1. Reopen Studio and the project.
2. Explain the restored Goal, Plan, Job, ChangeSet, cost, and next safe action.
3. Resume, retry, cancel, stop, or remove presentation as the visible state
   permits.
4. Confirm the same operation was not billed or applied twice and unrelated
   edits were preserved.

## Journey E — Verify, package, and continue

1. Ask Copilot to run validation, reference scans, tests, deterministic Replay,
   and required visual/audio checkpoints.
2. Let Copilot repair one supplied failing test and rerun the affected gates.
3. Build Windows Development and Release packages.
4. On the clean offline machine assigned by the observer, play menu-to-win and
   menu-to-lose loops in both packages without Studio, Node.js, Codex,
   credentials, or network access.
5. Return to the source project, inspect the build/security reports, close and
   reopen it, and make one small Copilot presentation change through the same
   review/test/build workflow.

When finished, leave the project and packages in the observer-assigned folder.
Do not alter collected evidence after signing the run record.
